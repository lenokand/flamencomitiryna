# Flamenco mit Iryna

Статический сайт на Astro + TypeScript: немецкая версия `/`, русская `/ru/`.

## Запуск

Установите Node.js 24 LTS и npm 10 или новее. В папке проекта:

```sh
npm ci
npm run dev
```

Откройте адрес, указанный Astro (обычно http://localhost:4321).

```sh
npm run build
npm run preview
```

Сборка выполняет проверку TypeScript/Astro и создаёт `dist/`. Папку `dist/` можно разместить на любом статическом хостинге. Открывать HTML двойным щелчком не следует: используйте локальный сервер.

## Редактирование

- `src/data/site.ts` — все тексты DE/RU, расписание, адрес, ссылки, учебные карточки.
- `src/pages/[...lang].astro` — общая структура обеих языковых версий.
- `src/styles/global.css` — адаптивный дизайн.
- `public/media/` — готовые изображения, постеры и три видео.
- `astro.config.mjs` — адрес сайта и базовый путь.

Расписание взято из предоставленной информации: понедельник 14:00–15:00, Sous Soul / Theaterstudio, Spitalgasse 4, 3011 Bern. На сайте есть просьба проверять изменения в группе WhatsApp. Даты будущих воркшопов не выдуманы. Montagscafé указано только в благодарности и как место отдельных воркшопов.

## Медиа

Использована предоставленная вырезанная фигура Ирины с веером. Изображения WebP имеют адаптивные размеры; видео H.264/AAC подготовлены для потокового начала воспроизведения (`faststart`), без автозапуска и с `preload="none"`. Постеры загружаются вместо видео до запуска. Доступны стандартные элементы управления, скорость и повтор. Запуск одного видео ставит другие на паузу.

Для повторной обработки положите исходники в `media-source/`: `hero.png`, `portrait.png`, `video-1.mp4`, `video-2.mp4`, `video-3.mp4`, затем:

```sh
npm run media
```

Исходники не нужны для обычной сборки. `media-source/` исключён из Git. Скрипт использует sharp и ffmpeg-static, который скачивает FFmpeg при установке зависимостей. Проверьте разрешение участников на публичное размещение материалов перед публикацией. Видео подписаны нейтрально: их точная учебная тема не подтверждена. Если в них есть важная речь, добавьте проверенные субтитры WebVTT и `<track kind="captions">` перед публичным запуском.

## Публикация на GitHub Pages — только по вашему решению

Ничего не опубликовано автоматически. Workflow запускается вручную, а не при push.

1. Создайте репозиторий GitHub и загрузите **содержимое этой папки**, включая `package-lock.json`, `public/` и `.github/`. Не загружайте `node_modules/`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Откройте **Actions → Publish GitHub Pages → Run workflow**. Это действие публикует сайт.
4. Дождитесь завершения `build` и `deploy`. Ссылка появится в результате deploy и в Settings → Pages.

В Actions конфигурация получает имя пользователя и репозитория из `GITHUB_REPOSITORY`: адрес `https://USER.github.io/REPO/` и все пути к ресурсам настраиваются автоматически. Для репозитория `USER.github.io` используется корень `/`.

Для своего домена задайте переменные репозитория **Settings → Secrets and variables → Actions → Variables**:

- `SITE_URL`: например `https://flamenco.example`
- `BASE_PATH`: `/`

Также настройте Custom domain в Pages и DNS. Для локальной проверки будущего адреса задайте эти же переменные окружения перед `npm run build`. Без них локальная сборка использует `https://example.com` только как временный адрес в SEO-метаданных. Workflow подставляет настоящий адрес автоматически.

## SEO и доступность

У каждой языковой версии свои title, description, lang, canonical, hreflang и Open Graph. Есть sitemap.xml, robots.txt и страница 404. Структура использует семантические разделы, ссылку пропуска навигации, видимый фокус, подписи элементов управления, alt-тексты и режим reduced motion. Тексты и ссылки работают без JavaScript; скрипт нужен только для дополнительных настроек видео.

## Расписание из JSON и календарь

Редактируйте `src/data/schedule.json`:

- `weekday`: 0 — воскресенье, 1 — понедельник, …, 6 — суббота.
- `startTime`, `endTime`: время в формате `HH:MM`, в пределах одного дня.
- `timeZone`: `Europe/Zurich` для Берна.
- `venue`, `address`: место и адрес; ссылки карты обновляются автоматически.
- `status`: `active` или `paused`. При паузе появляется уведомление, кнопка календаря скрывается.
- `excludedDates`: отменённые занятия, например `["2026-12-28", "2027-01-04"]`.
- `notice.de`, `notice.ru`: пояснение к расписанию на двух языках.

Изменения применяются после `npm run build` и новой публикации. Это редактирование файла, без панели администратора на сайте. Неверный день недели, время или статус останавливают сборку с ошибкой.

Кнопка «Добавить в календарь» создаёт **одно ближайшее занятие по регулярному расписанию**, пропуская отменённые даты. Google Calendar открывает заполненный черновик события; пользователь сам сохраняет его. Apple/Outlook получают файл `.ics`. Время рассчитывается в Europe/Zurich с учётом сезонного перевода часов. В событие включены адрес, оговорка проверки изменений и ссылка WhatsApp. Уже сохранённое событие не обновляется автоматически при изменении JSON. Для вычисления ближайшей даты и скачивания ICS нужен JavaScript.

Проверены летнее/зимнее время, прошедшее занятие, исключённая дата, пауза, параметры Google Calendar и формат ICS.
